# ChatGPT → Notion 작업 기록 프로토콜 (v1)

**적용 범위:** 사용자가 저장을 명시적으로 요청한 ChatGPT 작업. ChatGPT 대화 자동 수집이나 무인 자동 기록은 **미구현**.

## 저장 대상

- Notion `05 AI 작업 세션`: `collection://41c4bfd4-2eb4-81da-8801-000b2cfe99da`
- Notion `01 프로젝트`: `collection://41c4bfd4-2eb4-81d9-9ae6-000b764a437b`
- 중복 확인용 저장된 Notion 뷰: `view://41d4bfd4-2eb4-8102-b7fd-000c80e73bbc`
- Notion 작업 기록 운영 규칙: https://app.notion.com/p/41d4bfd42eb48168a968fed3e4c268c1

## 고유 작업 ID

- 형식: `SBG-YYYYMMDD-PROJECT-ACTION-V1`.
- 같은 논리적 작업의 재기록은 **같은 ID**를 사용합니다.
- 실제로 다른 작업이나 새 버전인 경우만 새 ID를 발급합니다.
- 저장 이전에 사용 가능한 **모든 기존 행**에서 `작업 ID`를 찾아야 합니다. 첫 검색의 누락, 조회 권한 오류, 조회 제한 또는 일부 페이지만 조회된 상태에서 새 기록을 생성하지 않습니다.
- 같은 ID가 있으면 **기존 페이지 링크를 반환**합니다. 내용이 바뀐 경우 사용자 지시에 따라 기존 항목의 해당 필드만 수정합니다. 기본 동작은 덮어쓰지 않기입니다.
- 같은 ID가 여러 건 있으면 추가 생성하지 않고 중복 충돌을 보고합니다.
- 이전 세션 중 ID가 없는 항목은 자동으로 일괄 수정하거나 삭제하지 않습니다.
- 일반 텍스트 `작업 ID`는 데이터베이스 수준 UNIQUE 제약이 아닙니다. 동시 쓰기 및 외부 직접 입력까지 완전하게 방지하지는 못합니다.

## 필드 매핑

| 필드 | 내용 |
| --- | --- |
| 세션 제목 | 작업명이 분명한 제목 |
| 작업 ID | 고유·안정 ID |
| 사용 AI | ChatGPT |
| 모델 | 확인된 모델만 |
| 작업 날짜 | 수행 일자 |
| 프로젝트 | 01 프로젝트의 **정확한 페이지 관계** |
| 지시문 | 사용자 요청 요약 |
| 결과 요약 | 완료 산출물과 실제 검증 증거를 구분한 요약 |
| 검증 상태 | 확인됨 / 부분 확인 / 미검증 |
| 인계 내용 | 미완료·오류·후속 실행 |
| 원본 대화 | 실재하는 링크가 확인될 때만 |

페이지 본문은 `목표 / 완료된 작업 / 검증 결과 / 미완료 / 다음 작업 / 보안·제약`으로 구분합니다.

## 저장 처리 순서

1. 실제 프로젝트를 조회해 정확한 Notion 프로젝트 페이지를 식별합니다.
2. 이미 합의된 작업 ID를 유지하고, 없으면 위 규칙에 따라 생성합니다.
3. 05 세션의 ID 검사 뷰를 **페이지네이션 끝까지** 조회합니다. 조회 실패 시 쓰기를 중단하고 실패를 보고합니다.
4. 동일 ID 1개면 재사용, 여러 개면 충돌 보고, 0개면 하나 생성합니다.
5. 생성 전 사용자 요청 및 실제 실행 로그를 대조해 완료·부분 확인·미완료를 구분합니다.
6. 생성 후 해당 Notion 페이지를 재조회해 ID·프로젝트 관계·결과 요약·검증 상태를 확인합니다.
7. Second Brain `/api/graph`는 **읽기 전용**으로 세션 및 연결을 보여 줍니다. API 조회 성공과 브라우저 화면 표시 성공은 분리해 보고합니다.

## 보안 및 제한

- 토큰, 비밀번호, 환자 식별 정보, 비공개 대화 전문을 저장하지 않습니다.
- Vercel 공개 클라이언트에는 쓰기용 API를 추가하지 않습니다.
- `GRAPH_VIEW_KEY`는 조회용으로만 사용하며 Notion 쓰기 권한으로 승격하지 않습니다.
- 비공개 연결 및 모든 대화의 백그라운드 자동 저장은 별도 인증·승인과 트리거 검증이 필요합니다.
